# Learning Path

The learning journey uses Pezza Pizza Store as one application, progressing from a local catalogue to a production-ready customer and restaurant experience. Each phase has a `01. StartProject` and a `02. EndProject` under `src/`; start with the former and use the latter to compare your result.

| Phase | Focus | Deliverable | Time |
|---|---|---|---:|
| 1 | Angular Fundamentals | Responsive pizza catalogue using local data | 3–5 h |
| 2 | Signals and Component Architecture | Reactive basket and component boundaries | 3–5 h |
| 3 | Routing and Application Structure | Lazy customer/admin routes and layouts | 3–5 h |
| 4 | Forms and Validation | Pizza customisation and validated checkout | 4–6 h |
| 5 | HTTP and OpenAPI Integration | Generated client-backed catalogue and orders | 5–8 h |
| 6 | State Management and Reactive Design | Persistent basket, order history, delivery tracking | 4–6 h |
| 7 | Testing and Code Quality | Unit, HTTP, E2E, and accessibility coverage | 4–6 h |
| 8 | Security and Authentication | Customer/admin identity integration and UI permissions | 4–6 h |
| 9 | Optimus UI and Advanced UX | Accessible, responsive storefront and admin UI | 4–6 h |
| 10 | Progressive Web Applications | Installable app with considered offline behavior | 3–5 h |
| 11 | Performance and Deployment | Optimized, containerized production deployment | 4–6 h |
| 12 | AI-Assisted Angular Development | Documented AI implementation and review workflow | 3–5 h |

Estimates include reading, implementation, and validation; prior Angular experience will change the actual time. Each phase README records prerequisites, learning outcomes, tasks, and validation instructions.

The first implementation increment is Phase 1. Later phase projects are intentionally staged rather than pre-populated with speculative code.
