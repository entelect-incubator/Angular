# AI Prompting Examples

## Learn a concept

> Explain the Angular concept used in this phase in the context of the Pezza start project. Point to relevant files, give a small example, and ask me a check-for-understanding question. Do not implement the exercise.

## Get implementation guidance

> Read this phase's README and inspect the start project. Help me implement task [task name] in small steps. First explain the approach and acceptance criteria; wait for my attempt before writing the solution. Follow the repository's Angular conventions.

## Review a change

> Review my diff against this phase's acceptance criteria. Report only actionable correctness, accessibility, maintainability, or test gaps, with file and line references. Do not rewrite the code. Check that the implementation uses the installed Angular APIs and does not introduce unnecessary dependencies.

## Improve a test

> Inspect the relevant component/service and its tests. Identify one user-visible behavior that is not covered, then propose a focused test using the current test runner and established project patterns. Do not replace meaningful assertions with implementation-detail checks.

## Check an architecture decision

> Compare this proposed design with the phase goal and `ARCHITECTURE.md`. Explain the trade-offs and whether the complexity is justified at this point in the learning path. Do not add a state library, abstraction, or dependency unless a concrete requirement needs it.
